# 源泉徴収票のローカル読取（v4.18.2検証版）
## 複数人の給与所得限定・一括一覧（次期Excel開発候補）

「操作画面」D3の **「複数人一覧」** から、源泉徴収票PDFの各ページを1人1行で読み込み、
専用シート **「一括計算一覧」** に並べます（最大100ページ）。

- 一覧にはページ番号、所得年、支払金額、給与所得控除後の金額、所得控除の額の合計額、源泉徴収税額、社会保険料、**寄附限度額の参考目安**、判定と日本語の保留理由を表示します。
- 計算対象は原票に記載された**給与所得のみ**です。年金・事業・不動産・雑所得、申告分離課税所得、その他の所得を混ぜません。**精緻な個別計算は従来の単独計算に限定**します。住民税通知書なしで全件確定する機能ではありません。
- 配偶者・特定親族・住宅ローン控除、地震保険料等の契約区分不明、税額不一致など**源泉票だけでは処理条件を証明できない行はHOLD（参考額空欄）**とします。生命保険料は、G30～G34の保険料内訳から所得税控除額G27を正確に再現できる通常ケースに限り住民税控除も再計算します。年少扶養人数G20を取得したケースは住民税非課税判定に反映します。年分・給与・所得控除・源泉税額・自治体の端数区分に重大な曖昧さがない場合だけ **「参考額（仮）」** を表示します。
- 一覧上の参考額は、追加所得・申告分離課税なしを**仮定した計算**です。原票にない他所得の不存在、扶養の事実関係、市町村条例などは証明できません。寄附実行前に単独計算・条件確認が必要です。
- **個別のXLSM案件保存では、一括一覧に他人の給与情報が残っている場合は保存を拒否します。** 一覧を別途保管する必要がある場合は、安全な保管方法を選び、専用シートの「一覧消去」操作を行ってから個別案件を保存してください。「新規入力」も確認後に一括一覧を消去します。
- 複数人の結果を1案件に合算しません。**一括一覧は現在の単独計算の入力欄・税制マスタを変更しません。** 個別XLSMを5件自動生成する旧案は廃止しました。
- PDFはローカルEXEで処理し、氏名・住所・個人番号・原本文字列を一覧・TSV・GitHub・CIに出力しません。CIでは匿名合成資料だけを使います。
- 特定扶養親族／特定親族特別控除の個別明細は単独計算でも**最大5人**（従来30人）。1～3人目は操作画面のD14:D16と連動、4～5人目は「特定親族明細」で入力します。超過はHOLDです。

この機能は **v4.18.35 の公開ZIPには含まれません**。新しい配布ZIPとWindows Excel実機による一括一覧・誤上書き防止の受入が完了するまでは、開発版/HOLDとします。


Windows配布ZIPに `FurusatoDocumentReader.exe` を同梱し、
Excelの「源泉票を取込」から呼び出します。利用者にPythonの導入は求めません。

埋込テキストPDFはG04等の記号と座標で読み取り、画像OCRと混同しません。
添付のように住宅借入金等特別控除可能額（G36）はあり、
所得税での適用額（G29）が空欄なら、差額からゼロを推定しません。
REQUIRES_REVIEWでも金額を**仮転記**でき、元のブックはバックアップします。
自動計算された寄附限度額は原票照合完了まで表示されません。
「読取内容の確認」で源泉徴収票の参考値との一致を確認する方式です。
**納税者の切替確認：** 読取結果の取込を承認した後、源泉徴収票が別の納税者のものか確認します。「はい（別の納税者）」では前案件の公的年金・事業所得・雑所得・申告分離課税所得・特例状態などを初期化し、「いいえ（同じ納税者の再取込）」では**同じ所得年の場合に限り**これらの別途入力値を維持します。**所得年が異なる場合は同じ納税者でも前年の追加所得を初期化**し、画面で理由を通知します。既定は「キャンセル」です。読取ファイルには本人識別情報を連携しないため、ソフト側で同一人物と推定して自動引継ぎすることはありません。どちらでも扶養親族・源泉徴収票の各入力内容は再確認が必要です。新規取込前には元のブックのバックアップを作成します。

**複数ページPDF：** 1つのPDFに複数の源泉徴収票が収録されている場合、読取EXEがページ数だけを先に確認し、Excelで対象ページ番号（1～最大100）を選択します。未選択・番号範囲外なら取り込みません。選択した**1ページのみ**を読み取り、他ページの給与・控除などを合算しません。選択した「対象ページ／総ページ数」は転記確認の画面に表示し、取り込み後も個人情報を含まない `SELECTED_PDF_PAGE_番号_OF_総数` を確認情報に残します。選択したページは必ず仮転記・原票照合対象（`MULTIPAGE_SELECTED_PAGE_REVIEW`）です。PDFの氏名・住所等は取得・送信しません。ページ数の先行確認は `--page-count`、対象ページの選択は `--page N` で実行します。ページ選択を取り消した場合も一時JSON/TSVを削除します。

画像OCRは日本語Tesseract辞書等の同梱が未完成であり、引き続き検証版です。

源泉徴収票の氏名・住所・個人番号はGitHub・CIへ送信しません。
通知書が届く前に限度額を算定するため、住民税通知書の入力は求めません。
公的年金・事業所得・雑所得は所得年の収入・経費から算定します。

控除可能額G36が存在するのにG29が空欄の場合、G05-G06が非正で源泉税G08が0のときだけ、G29の所得税適用額を0と安全推定します。課税所得が正のケースは従来どおり確認対象です。G05/G06/G27/G28をPDFから取得できた場合は、それぞれの原票値を計算に優先利用します。読取のたびに元データはバックアップします。

## 公開後の5ページ源泉徴収票読取の修正（v4.18.35後続候補）

公開済み `v4.18.35` の読取EXEは、PDFの文字レイヤーが印刷順とは異なる
国税庁形式の源泉徴収票で、印刷された所得年が読めるのに `YEAR` が空欄となり、
Excelが「所得年を認識できません。」と表示する場合がありました。

後続候補では、従来の「令和 N 年分」テキスト検索に加え、
**左上の `L01 → 令和 → 年数字 → 年分` の位置関係**から年分を特定します。
異なる年が検出された場合は採用せず、確認対象に留めます。住宅ローンの居住開始日等、
源泉票中の別の「令和」から年分を推定することはありません。

また、テキストPDFで `G26` の枠が存在しても社会保険料の金額が空欄の場合、
仮の0円を転記し `BLANK_SOCIAL_INSURANCE_REQUIRES_REVIEW` を付けます。
**これは確認済みの0円ではありません**。原票で空欄か、読取漏れかを照合するまで
`REQUIRES_REVIEW` を維持します。印字された金額がある場合は従来どおりその額を採用します。

**複数人PDFの扱いは変更していません。** 現行Excelブックは1案件（1納税者）単位です。
5ページから任意の1ページを選ぶ既存仕様は、別人の収入・控除を合算したり、
先に取り込んだ案件を黙って置換する事故を防ぐためのものです。
5人分を保存する場合は、ページ1～5をそれぞれ選択し、**各人別のXLSM案件ファイル**に
保存します。全ページを一操作で独立案件5件へ展開する機能はまだ未実装です。
本修正を反映した新しいWindows配布物が完成・受入されるまで、
**公開済みv4.18.35のEXEの挙動は変わりません**。

実原票・氏名・住所・個人番号・金額をGitHub/CIへ格納せず、合成値の回帰テストのみを追加します。

## 令和8年分の特定親族照合（v4.18.2）

- 源泉徴収票の `G72` は「特定親族の人数」、`G73` は「特定親族の従人数」、`G20` は「16歳未満の扶養親族の数」、`G74` は「特定親族特別控除の額」。旧G73→年少扶養の対応は誤りであり、令和7年・令和8年の添付原票の欄位置を確認して修正しました。
- G72 または G74 が存在する書類は、必ず仮取込 `REQUIRES_REVIEW` とします。G72/G74 は「追加所得」画面の読取専用 B38/B39 に保持し、年少扶養 G20 を「操作画面」D23 に取り込みます。G73が正数の場合は未対応の特定親族従人数を他の扶養人数へ流用せず、`UNSUPPORTED_SPECIAL_RELATIVE_SUBORDINATE_COUNT` によりHOLDとします。
- 確認には「操作画面」A3の「特定親族明細」リンクから最大5人分を入力します。1～3人目の合計所得は操作画面 D14～D16 と連動し、4～5人目は明細シートに個別入力します。各人の年末年齢・合計所得・適用要件を確認し、**特定扶養控除**と**特定親族特別控除**を区別します。
- G72の人数は**特定親族特別控除の対象者数だけ**であり、特定扶養控除の人数を含めません。VBAの「読取内容の確認」は、明細5人を個別に再計算してG72人数・G74控除額と**完全一致**させます。原票と1円でも異なる場合や、要件未確認者が残る場合、確認済みへ移行しません。
- **G72=0／G74=0が原票から明示された場合も照合対象**です。空欄と数値ゼロを区別し、ゼロ人との表示に反して特定親族特別控除対象者が入力されている場合は、確認済みにできません。G72/G74の双方が空欄の場合に限り、その項目の原票照合を省略します。
- 読取内容の確認スナップショットは、入力ごとに**文字数を付けた形式**で照合します。区切り文字を含む入力でも別の入力状態と誤一致しないようにしており、旧方式での確認履歴は自動承認せず、再確認が必要になります。
- 6人以上を示すG72、負数・小数の人数、控除額の不正値は確認対象外として停止します。検証用マクロは非対話型でこの同じ照合処理を呼び出しますが、**源泉徴収票の確認状態を書き換えません**。
- 入力変更時には前回の原票確認スナップショットが失効します。実顧客の源泉徴収票をGitHubのテストデータとして使わず、テストでは合成データのみを使用します。
- 2025年分の特定親族所得要件は58万円超、2026年分は62万円超。令和8年分の法改正は同年12月1日施行を前提にしているため、施行前の準確定申告は正式対象外です。
- 国税庁 No.1177： https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1177.htm

氏名・住所・個人番号・現物PDFをGitHubやCIへ登録しない方針は変えていません。今回の試験は匿名の項目座標・数値のみです。
## 構造化データ（CSV・TSV・JSON）の重複・破損入力の拒否（2026-11-15）

Excelへ仮転記する前に、**CSV/TSVの `field,value` 2列構造**と各行の列数を検査します。
同じ項目（`year`、`salary_gross`、`social_insurance` 等）が複数行にある場合、
値が同じでも異なっていても、後勝ちで上書きせず読取エラーで停止します。
JSONはトップレベル・`fields` 内を含め、重複オブジェクトキーを禁止します。

いずれも**VBA向けブリッジ出力を作成しません**。値の曖昧さが解消するまで、
読取不能を計算成功や源泉徴収票の確認済みとして扱わない安全対策です。
新しい検証は架空の金額・氏名なしの構造化ファイルで行い、
実原票や個人識別情報をGitHub・CIへ転送しません。
既存の税率・税制マスタ、住民税の算定式、通常のPDF読取方式は変更しません。

## 任意の控除額に不正値が含まれる場合のHOLD（2026-11-15追補）

CSV・TSV・JSONで認識対象となる給与・税額・控除等の項目に、
整数でない値、負数、過大値、真偽値などがある場合は、
必須3項目が正常であっても `INVALID_STRUCTURED_FIELD` で
`REQUIRES_REVIEW` とし、自動的な計算可能判定をしません。
不正値そのものはExcelへ仮転記せず、警告のみ残します。
また、JSONの所得年は整数型のみ受け付けます（`2026.0` は不可）。

Gコードがない項目名付きテキストに、同じ給与・控除項目が異なる金額で
複数回現れた場合は `CONFLICT_項目` を付けてHOLDとし、
後の金額による黙示的な上書きを禁止します。
同額の繰返しは矛盾とは判定しません。

上記は読取の安全性改善であり、税法上の控除額の検証済み・実原票5件の
寄附限度額完全一致を意味しません。検証ケースはすべて架空資料です。

「読取内容の確認」のVBA処理は、B32の警告に `UNSUPPORTED_` が含まれる場合、確認済みへ変更しません。単なる確認チェックで未対応の特定親族従人数を解消済みに見せることを禁止します。原票の条件を別途確認できるまで限度額はHOLDです。

## 項目名付きテキストの未判読控除を無視しない（2026-11-15）

テキスト・PDF文字列のフォールバックで、認識済みの項目名（例：
「地震保険料の支払額」）に数値以外の値・単位つきの未正規化文字列・
空欄がある場合、その項目をゼロ扱いせず、
`INVALID_LABELLED_項目コード` として `REQUIRES_REVIEW` にします。
認識していない一般のラベルや個人識別情報は引き続き転送しません。
同じ項目で正しい値と不明値が混在するときも、既存の数値を
無条件採用しません。テストには氏名・実税額のない架空資料だけを使用します。

## 不正な所得年の丸め込み防止（2026-11-15）

JSONの年分が数値小数（例: 2025.6 / 2026.0）、文字列、真偽値の
いずれかであれば、読取結果の年分を空欄にし、`YEAR_NOT_APPROVED`
かつ `REQUIRES_REVIEW` として取り扱います。
VBAでも、年分に`CLng`を適用した後で**元の文字列表現と一致すること**
を確認し、2025.6→2026のような自動丸めを拒否します。
正常な整数年分2025/2026は従来どおり受け入れます。
実原票や個人情報をCIへ渡さず匿名の合成入力で検証します。

## 年末調整の所得税独立検算（2026-11-15追加）

手元の源泉徴収票をオフラインで検算できます。原票PDFや数値は
GitHub・CI・外部サーバーへ送信しません。

`python tools/audit_withholding_reconciliation.py --input "源泉徴収票.pdf" --all-pages`

年末調整後の給与所得金額（G05）、所得控除合計（G06）、源泉徴収税額（G08）、
住宅借入金等特別控除の所得税適用額（G29）をもとに、独立した税率帯の
限界税率計算、1,000円未満切捨て、102.1%乗算・100円未満切捨てにより
源泉徴収税額を再現します。住宅ローン控除可能額（G36）と適用額（G29）を混同しません。
住宅ローン控除可能額のみ存在し、所得税への適用額がない場合、課税所得がゼロかつ
原票の源泉税額もゼロのときだけ適用ゼロと判定します。

標準出力にはページ番号・`MATCH / MISMATCH / NOT_COMPARABLE` の判定・
理由コード・集計件数だけを記録し、氏名、給与額、控除額は出力しません。
高所得の最低税負担特例や別の税額控除など、検算式がカバーしないケースは
一致しない場合もあり、`MISMATCH` は即座に原票誤りを意味しません。

**注意：当該検算は源泉徴収税額だけの検証です。住民税所得割額、
自治体別の端数処理、他の所得、配偶者・扶養・住宅ローン控除の住民税配分、
申告方式を検証するものではなく、ふるさと納税限度額は常に
`NOT_VERIFIED` のままです。**

- 国税庁「年末調整のしかた」：https://www.nta.go.jp/taxes/shiraberu/taxanswer/gensen/2662.htm
- 国税庁「所得税の税率」：https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/2260.htm


## 給与所得だけの寄附上限・住民税所得割の独立合成検算（2026-11-15）

別実装の `tools/audit_salary_donation_limit.py` は、**架空給与案件のみ**を対象に
調整控除後の住民税所得割額（市町村と都道府県をそれぞれ100円未満切捨て）、
人的控除差と基礎控除差を考慮した寄附特例控除率、所得割の20％上限、
総所得金額等の30％上限を有理数演算で照合します。
実際の源泉徴収票を読まず、所得年・給与所得金額・住民税所得控除合計・
人的控除差・標準税率の市区分を**全て独立確認済みの匿名入力**とみなします。

`python tools/test_salary_donation_oracle.py` で自治体の公表例（源泉後給与所得
202万円・住民税所得割114,500円・上限約28,974円）と、
従来のExcel合成ケース（給与収入700万円・所得割374,500円・
千円単位の参考上限109,000円）をテストします。2025/2026年を検証対象とし、
正式ブックへの数式変更は行いません。

戻り値の `scope=SYNTHETIC_ONLY` と `donation_limit=NOT_VERIFIED`
は常に保持します。配偶者・扶養、住民税非課税、住宅ローン控除、
医療費控除、分離課税やその他税額控除等の未検証実案件へ転用してはなりません。
住民税決定通知書を用いた照合は要求しません。年末調整済みの給与所得のみで条件を個別確認できるケースでは、源泉徴収票の同年分G04/G05/G06/G08から所得税・住民税所得割・寄附限度額を独立に再計算し、Excelの限度額と照合します（詳細は docs/salary-only-withholding-independent-audit.md）。その他所得や所得控除・住宅ローン控除等、当年の条件が不足する場合は推測せず個別確認が必要です。

## 2025・2026年の配偶者・扶養・住宅ローン複合検証（2026-11-15）

### 前年の源泉徴収税額と所得金額調整控除の誤流用防止（2026-11-16）
