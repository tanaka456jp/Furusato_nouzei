# 源泉徴収票専用・端末内OCRの品質受入基準（2026-11-09）

## 対象と守るべき条件

目的は、HousingERPの**帳票完全性・OCR数値整合性・異常時の登録禁止**と、TaxTheoryAudioAppの**Apple Vision・画像補正・領域再認識の思想**を公開Webへ応用すること。元プロジェクトのコード・保護された個人データを公開リポジトリへ転載しない。HousingERPで利用する有料のGoogle Cloud Document AIと、TaxTheoryAudioAppのiOS専用Apple Visionは**ブラウザで直接利用できる同一OCRエンジンではない**ため、両者の過去の結果をWeb版の品質実証に流用しない。

現在のコードは `Tesseract.js 7.0.0 + jpn 1.0.0 + PDF.js 6.3.289` を公開サイト内に同梱する。入力された画像・PDFは端末外送信せず、原票をサーバーやlocalStorageへ保存しない。ライブラリ/モデルは同一ホストから取得する。CSPは原則外部通信を禁止し、`connect-src 'self'` は同梱資産の配信に限定する。

## 機械的な手順と限界

1. 電子PDFの文字情報をブラウザ内で直接抽出する。複数ページはHOLD。文字不足の場合は同一端末上でPDFを画像化してOCRへ。
2. JPEG・PNGまたは画像化したPDFはCanvasで解像度を制限し、原画像と輝度/コントラスト補正画像を作る。
3. Tesseract.js（同じOCRエンジン）の**原画像と補正画像を2回認識**する。読取信頼度はいずれも75以上、年分・4項目が完全一致した場合だけ候補を表示する。**同一OCRエンジンの2回認識には相関誤りがあるため、独立したAI OCR2機比較の代わりとはみなさない。**
4. 源泉徴収票のタイトル、令和7/8年分（2025/2026）、支払金額、給与所得控除後の金額、所得控除の額の合計額、社会保険料等の金額を確認する。文字列の推測補正・金額の自動穴埋め・複数候補の都合のよい選択は禁止。
5. ページ/年分/金額の不明・不一致・重複・OCR低信頼度ではHOLD。候補が一致した場合も `REQUIRES_SOURCE_REVIEW` を維持。**本人が原票と追加控除・扶養の有無を視認して明示確認するまで入力欄へ転記しない**。
6. 転記後も独立した税額エンジンの源泉徴収票参照値・年分・法定所得控除・所得税/住民税等の照合を通し、未対応条件で寄附限度額は表示しない。

**2026-11-09追加**：`ocr-quality.js` で明らかに不適切な画像（単色・極端な暗さ・透明・解像度不正）をローカルでHOLD。`ocr-layout.js` はPDF.jsの文字座標が使用可能な場合、項目名近傍の金額が全文抽出結果と矛盾するケースをHOLDにする検査に加え、**見出しと数値が別々の文字領域に分かれる電子PDF**から、源泉徴収票の表題・年分の3要素・4金額欄の位置関係が全て一意な場合に限り、原票目視確認用の候補を作れます。曖昧・重複・矛盾があればHOLD、座標抽出が不確実なら画像OCR側へ移ります。候補は税額を自動確定せず、原票確認・税額エンジン検査が必須です。OCR処理中の原票差し替え・年分変更・リセットは進行中の結果を無効化し、旧画像の値を転記させません。

未実装：Webでの台形/遠近補正、OCRで不鮮明な数字だけの実座標再認識、実源泉徴収票に基づく撮影ガイドの閾値調整、HEICの安全な変換、Safariの実端末確認。これらはTaxTheoryAudioAppの画像品質判定とHousingERPの原票差分監査を参考に、別途検証して実装する。文章全体が一致するだけでは金額項目の正しさを保証しない。

## AI OCR比較のベンチマーク（まだ未測定）

**同じ原票の正解データ**に対し、電子PDF・複合機スキャン・スマホ画像・低照度・回転/傾き・数字が近接する様式・令和7/8年分を層別評価する。

| 指標 | 定義 | 受入案 |
|---|---|---|
| 重要4項目の完全一致率 | 正解と完全一致した件数／正解欄の総数。HOLDも成功には数えない | 99.5%以上を目標 |
| 1帳票全項目一致率 | 年分＋4項目が全部正解の帳票数／帳票総数 | 99.5%以上を目標 |
| 誤った候補が転記可能になる件数 | 間違った欄値に対し `eligibleForManualTransfer=true` となった件数 | **0件**を必須条件とする（観測0件でも母集団への保証ではない） |
| HOLD率 | 誤判定を含むすべての中止件数／原票総数 | 別途明示（安全性だけでなく操作性も評価） |
| 認識時間・メモリ | PC・iPhone、端末内だけで計測 | 実測後に閾値を決定 |
| 外部送信 | 原票・全文・金額のネットワーク送信 | **0件**（同梱コード・学習データのGETは除く） |

判定時は、原票形式別の標本数、信頼区間、失敗の内訳、機種/OS/ブラウザ、Tesseract/PDF.js版、事前処理版を記録する。低件数の100%と大規模での99.5%を混同しない。商用AI OCRと比較する際は**同じ原票・同じ真値・同じ項目単位**で計測する。

### 添付原票の非公開・読取専用構造診断

開発環境に存在する添付済み源泉徴収票PDFの**1ページの文字領域と座標のみ**を読取専用で診断したところ、4金額欄の見出しと数値は別の文字領域であり、和暦の「令和」「数字」「年分」も分割されていました。近接座標の条件下で各4欄の数値候補は一意で、和暦年分の組も1組でした。本文・金額・氏名・住所・原票画像をGitHubやActionsへ登録していません。これは実ブラウザ/PDF.jsでの認識成功、数値正解、OCR精度の証明ではありません。実画像とPDF.jsの挙動を別途非公開で検査する必要があります。

### 限定的な写真四隅検出・遠近補正（追加）

`ocr-perspective.js` は、**暗い背景の上に四隅まで写った明るい帳票**に限り、端末内の低解像度サンプルから最大連結明色領域の四隅を検出し、射影変換してから原画像／コントラスト補正画像の2回OCRへ供する。背景が明るい、四隅が隠れる、複数の白い物体が接する、輪郭が不明瞭などの場合は補正を行わず、従来の経路に戻す。補正成功は帳票・金額の正当性やOCR精度の保証ではない。補正後も画像品質、年分、重要4金額の二回一致、原票目視確認、税額計算HOLDを維持する。合成ピクセルのみの幾何学回帰をCIで実行するが、実写精度は未評価である。

### 非公開原票の独立真値ベンチマーク集計

`public-web/quality/score-private.cjs` は、所有者の端末でのみ真値（年分・重要4金額）と抽出結果を照合する**集計専用**ツール。公開リポジトリやCIには合成データのテストのみを登録する。

入力はローカルの標準入力JSON（`{"records":[{"format":"digital-pdf","truth":{"year":2026,"salaryGross":7000000,"salaryIncomeReference":5200000,"deductionsReference":1670000,"socialInsurance":1000000},"result":{"eligibleForManualTransfer":true,"year":2026,"candidates":{"salaryGross":7000000,"salaryIncomeReference":5200000,"deductionsReference":1670000,"socialInsurance":1000000}}}]}` は**合成例**）。形式は `digital-pdf`, `scan-pdf`, `photo`。例：`node public-web/quality/score-private.cjs < PRIVATE_TRUTH.json`。実原票・真値ファイルは**Gitに追加しない**。出力は各形式の件数、一致件数、一致率、Wilson 95%下限、HOLD、誤候補の転記可能件数のみで、原文、ファイル名、個別金額は出さない。

HOLDは一致に数えない。誤りが1件でも転記可能なら危険な候補として計上。1件の100%を99.5%実証とは扱わず、`accuracyCertified:false` と `release:HOLD...` を固定している。正解データの独立採録、形式別母数、端末/ブラウザ別実測と検証者の承認は別途必要。

### 金額欄の拡大再認識と測定基盤（追加）

- `ocr-regions.js` はTesseract.js v7の `blocks` 出力から**4項目の行と画像領域がすべて一意**のときだけ、合成的に矩形を選びます。全文の元画像・コントラスト補正画像が既に同じ4値を返す場合に限り、矩形を2倍の画素数へ拡大して追加OCRで再照合します。認識文字・信頼度（75未満）・候補値が一致しなければHOLD。`blocks` が得られない／矩形が曖昧な場合は追加読取をSKIPし、**既存の二回全文照合を上書きしません**。この処理は同じTesseractモデルの再認識であり、異なるAIモデルによる独立照合ではありません。
- `test-ocr-regions.cjs` と `test-ocr-region-dom.cjs` は**架空の源泉徴収票と合成矩形**で、欄位置限定、明らかな誤額のHOLD、OCR信頼度、原票確認前転記禁止を検証。 `test-ocr-browser-smoke.cjs` では実Chromiumで `blocks` フォーマットの取得が可能かを確認。実物のOCR正答率は証明しません。
- `scripts/ocr-accuracy-metrics.cjs` で実原票の正解値と**本人の端末内で得た候補結果**を照合するための匿名集計機能を追加。正解値・ファイル名・全文は標準出力に一切含まず、`digital_pdf`、`mfp_scan`、`mobile_photo`、`other`ごとのサンプル数、4項目完全一致率、帳票単位完全一致率、誤った候補の転記許可数、HOLD数、95% Wilson区間の下限だけを表示します。これは**試験基盤**であり、現時点の計測は架空データのみです。

#### 実原票のローカル計測手順（公開データへの送信禁止）

本人の端末だけに `public-web/.private/ocr-benchmark/` を作成し、手動で正解を照合した記録を `sample.json` として保存します。利用目的・保存期間と端末の保護を確認し、テスト後は安全に廃棄します。実原票画像やOCR全文をGitHub・Actions・Artifacts・相談チャットへ転送しないでください。

```powershell
node public-web/scripts/ocr-accuracy-metrics.cjs public-web/.private/ocr-benchmark/sample.json
```

入力JSONは、公開しても害がない**架空の構造例**として次の形式です。

```json
[
  {
    "kind": "digital_pdf",
    "truth": {"year": 2026, "salaryGross": 7000000, "salaryIncomeReference": 5200000,
              "deductionsReference": 1670000, "socialInsurance": 1000000},
    "review": {"eligibleForManualTransfer": true, "year": 2026,
               "candidates": {"salaryGross": 7000000, "salaryIncomeReference": 5200000,
                              "deductionsReference": 1670000, "socialInsurance": 1000000}}
  }
]
```

**誤った値が転記可能だった件数は0件を目標**とし、項目正解率99.5%以上も検証しますが、統計上の信頼区間が広い少数例で「市販AIと同等」とは評価しません。個別の誤りの原因調査・原票確認は、一般公開データに変更せず私的環境で行います。これはAdSenseや税額計算エンジンの正式公開を許可するものではありません。

### 完全取得した電子PDFの全文・座標値不一致は強制HOLD

2026-11-09追加監査：従来の配置近傍検査 `audit` が `PARTIAL` になる場合、全文解析と別経路の座標別抽出がそれぞれ4金額を完全取得しても、両者の相違が転記判断に反映されない経路があった。 `crossCheckExtracted` を追加し、両者が完全抽出の場合に年分および4金額すべてを直接突合する。**1円でも違えばHOLDし、個別金額をログに出さない。** 比較可能でない場合は候補を自動昇格させず、従来の欠落・重複・座標監査・本人確認ゲートを維持する。両者は同じPDF文字層由来であり独立した原票真値確認とは扱わない。合成1円差の回帰検証をCIへ追加。

### OCR候補の提示中・認識中に行われた手入力を優先

2026-11-09追加：4金額のいずれかが手入力で変更された場合、認識中または候補表示中のOCR結果を即時失効し、転記ボタンを無効化する。認識開始時の改訂番号と結果受信時の改訂番号を照合し、遅延結果による上書きを禁止する。既にOCR転記した後に4金額を利用者が変更した場合も、旧原票の照合済み表示を解除し、寄附目安額をHOLDとする。入力をクリアして手入力をやり直すか、新原票のOCRと目視確認を実施する。原票本文・個別値はログに出さない。合成JSDOMの操作回帰で検証する。

### PDF文字層のメモリ・入力境界

PDF.jsの `getTextContent()` の文字要素を連結する前に、要素数最大4,000、要素文字長最大240、合計文字長120,000を上限として厳密検証する。各文字要素の座標配列は6個の有限数値であることを要求する。上限超過や異常構造の場合、元の全文・金額候補を返さずHOLDする。ファイルサイズ8MB以下であっても、圧縮された異常なPDFから巨大な文字列が生成されうるための保護。数字は推測補完しない。上限値は正式な実原票形式別ベンチマークで調整する。現状は `getTextContent()` 呼出し自体のメモリ使用量を完全には制限しないため、正式受入まで追加監査する。

### Safari画像デコードの互換経路

`createImageBitmap(file,{imageOrientation:"from-image"})` が存在していても、端末・JPEG形式・APIオプションの組合せによりデコードが拒否される場合がある。画像デコードAPIの拒否時だけ、同一端末内の `Image`/Blob URLによる画像読込へフォールバックする。Blob URLは必ず失効し、画像データのネットワーク送信・保存はしない。いずれの経路も従来の画像寸法・品質検査、OCR二回一致、手動目視転記ゲートの対象。JSDOM合成JPEGでデコード失敗時の切替・オブジェクトURLの破棄・外部通信0件を回帰検証する。**iPhone実機Safariでの動作保証ではない。**

### 画像のみのスキャンPDFとPDF文字層異常の区別（追加）

`boundedTextLayer` はPDF.js文字要素0件を**`EMPTY`**と判定する。これは破損を意味しないため、1ページPDFをブラウザ内で画像化して既存の画質判定とTesseract二回認識へ進む。文字要素数・長さ・座標の異常は従来どおりHOLDとし、OCRへ無条件フォールバックして異常を隠さない。PDF.jsが返す非テキストマーク要素だけの場合も、実文字要素0件として扱う。白紙PDFは画質検査でHOLD。合成RGB画像XObjectのみの1ページPDFを実Chromium・PDF.jsで開き、文字要素0件、画像OCR経路、明示確認前の転記禁止、白紙HOLD、外部通信0件を回帰する。**実原票OCRの精度評価ではない**。

### PDF.js 6系と旧ブラウザのMap API互換性

2026-11-09の実Chromium 141で、PDF.js 6.3.289による合成画像PDF描画時に `this[#methodPromises].getOrInsertComputed is not a function` を確認。PDFファイルの破損ではなく、ブラウザにES2026 Map補助APIが未実装であることが原因。公開Web内に `pdf-compat.js` を同梱し、`Map.prototype.getOrInsert` と `Map.prototype.getOrInsertComputed` が未実装の場合だけ非列挙で補完する。既存ブラウザ実装を上書きせず、通信・保存・原票処理は増やさない。Node単体合成契約とPDF.js実Chromium描画による検証を行う。実Safari・実Edgeでの確認および原票の精度実証は別途必要。

### PDF.js読込タスクの終了・メモリ解放

PDF.js 6.3.289の `getDocument()` が生成する `PDFDocumentLoadingTask` と、その `.promise` により得られるPDF文書プロキシを区別する。後者が `destroy()` を持つとは限らないため、成功・読取失敗・複数ページ拒否のすべてで**読込タスクの `destroy()`** を呼び、WorkerやPDFデコード資源の解放を試行する。生の画像・テキストは保存しない。大量連続スキャンにおける実端末メモリ増減は未測定であり、正式公開前に実測する。

### PDF全文に異なる所得年が混在する場合のHOLD（2026-11-10）

全文テキスト抽出が2025年と2026年の両方を明示的に検出した場合、座標抽出で2026年等の1年分・4金額が一意でも**転記候補をHOLD**する。分割文字層のため明示的な年分が検出できない場合とは区別し、適切な座標抽出を維持。元テキスト・氏名・個別金額はログ化しない。合成サンプルで矛盾のある所得年を検出する回帰テストを実施。独立した実原票によるOCR精度・法令正確性の証明ではない。

### OCR出典照合が失効した後の差し替えと手入力保護（2026-11-10）

OCR転記した値について、画面の年分照合済みフラグを手入力変更で失効させた後も、セッション内メモリだけに**元の4欄の値と各欄の手修正履歴**を保持する。ファイル再選択・取消し・年分変更では、旧OCR由来で未修正の値のみを空にし、手入力で修正した値は保持する。OCR転記履歴がない場合は、給与所得控除後・所得控除合計の手入力した検証欄も勝手に消去しない。新しいファイルが選択されれば計算をHOLDし、出典違いの古いOCR値で試算を許可しない。情報はブラウザ内メモリのみで、通信・localStorage・ログへ保存しない。JSDOM合成原票で転記→手修正→旧OCR3値消去→手入力保持を回帰する。
